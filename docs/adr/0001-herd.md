# ADR 0001: herd — a Substrate-API-compatible microVM actor runtime

- Status: accepted for R0 (issue PLT-112, program PLT-111)
- Date: 2026-10-30
- Spec: Everdict workspace `docs/specs/architecture/herd.md` rev 2 (with the rev 3 owner decision R-D10), which amends
  `herder-everywhere.md` (PLT-101)

## Context

Everdict needs an actor layer — checkpoint/restore, a warm pool keyed by template, resume-on-request ingress, a
per-actor egress gateway with credential injection — on hosts that have no Kubernetes. Nomad has none of it, and
Everdict rebuilt pieces of each inside its control plane. Substrate has all of it, but only on Kubernetes. Substrate's
useful core is its API and lifecycle model (`api/ateapi/v1/ateapi.proto` at commit `6d7b3f49`) and the in-actor guest
API of `agent-substrate/env`; its microVM class is Kata + Cloud Hypervisor with containers' rootfs as a host overlay,
DurableDir volumes over one virtio-fs share, and memory snapshots.

No single VMM gives memory snapshots on both macOS and Ubuntu, so herd uses one per platform and makes each host
declare what it can do.

## Decisions taken from the spec

### R-D1 Build our own, as a separate product

**Decision.** herd is built as a separate product in its own repository, `github.com/everdict/herd`, usable without
Everdict. It runs on a Nomad cluster and on hosts with no cluster tool (one host, or several hosts that only share a
network path to herd-api).

### R-D2 Speak Substrate's API

**Decision.** herd-api implements a pinned subset of Substrate's `Control` service plus a capability extension
(`herd.ext.v1.Capabilities`). Everdict keeps one runtime integration — the Substrate API — for real Substrate and for
herd, and one conformance suite runs against both. The subset and its pin are A-4; the extension is A-5.

### R-D3 Components

**Decision.** herd has the roles Substrate has, as five components: `herd-api` (records, scheduler, suspend/resume
workflows, snapshot store, authn/authz), `herdlet` (the node agent; it dials out, no inbound port), `herd-router`
(resume-on-request ingress over node tunnels), `herd-egress` (default-deny egress, hostname rules, credential
injection) and `herd-guest` (the in-VM agent).

### R-D4 Deployment modes

**Decision.** Three deployment modes on one code path: all-in-one (one host, SQLite), multi-host join with no cluster
tool (`herdlet join`), and Nomad (herd-api as a service job, herdlet as a system job; Nomad supervises the processes,
herd places the actors).

### R-D5 Language

**Decision.** herd is written in Go (module `github.com/everdict/herd`, A-2).

### R-D6 Everdict's laws carry over

**Decision.** Everdict's laws hold in herd: a delete is answered gone, present or unknown, and unknown is never folded
into absent; state is durable before release (a snapshot is not reported until it is complete, and an actor's VM is
not released before its snapshot is); no credential in the actor (herd-egress injects credentials outside the VM).
In R0 the `vmm` interface already answers presence in three values and its contract suite checks that a timed-out or
unanswered call is unknown, never gone (A-6).

### R-D7 Every actor is a Linux microVM

**Decision.** Every herd actor is a Linux microVM, in all three deployment modes. Inside it, the actor's ActorTemplate
defines containers (OCI images run by crun under herd-guest) and volumes (DurableDir subdirectories of one virtio-fs
share), as in Substrate's microVM class. There are no docker, runsc or Seatbelt backends in herd. A host without KVM
(Ubuntu) or Virtualization.framework (macOS, Apple Silicon) cannot join, and `herdlet doctor` says why.

### R-D8 One guest, two hypervisors

**Decision.**
- Ubuntu (x86_64, arm64): Cloud Hypervisor (pinned, v54.0) + virtiofsd (>= 1.11); rootfs from read-only erofs/ext4
  images built from OCI layers plus a writable layer; network = TAP into herd-egress (nftables default-deny + proxy);
  control over hybrid vsock.
- macOS hosts (Apple Silicon, macOS 14+; 26+ for vmnet custom networks): Virtualization.framework via Code-Hex/vz; the
  same Linux guest kernel (arm64) and herd-guest; virtio-fs volumes; network = file-handle attachment into
  herd-egress's userspace stack (gvisor-tap-vsock); native vsock.
- The same guest kernel configuration, initramfs and herd-guest build for both architectures, arm64 and amd64 (A-7).
  A vsock transport adapter hides hybrid vs native vsock.

### R-D9 Capabilities are declared, not assumed

**Decision.** Each host declares `suspendMaxFidelity` and `restoreFamily` (in `vmm.Capabilities` and in
`herd.ext.v1.WorkerCapabilities`); the scheduler never assumes them.

| | Ubuntu (Cloud Hypervisor) | macOS host (Virtualization.framework) |
|---|---|---|
| suspendMaxFidelity | MEMORY (eager restore with virtio-fs) | VOLUMES (stop containers, keep volumes); MEMORY only if the host shows it can save machine state in its session — declared per host |
| restore elsewhere | within the same restore family = (CH version, arch, CPU feature class); otherwise VOLUMES | never at MEMORY (the save file is bound to one Mac and user); VOLUMES anywhere |
| restoreFamily | `microvm-ch-<arch>-<cpu-class>` | `microvm-vz-arm64-<host>` (memory) |
| portable family | `microvm-volumes` | `microvm-volumes` |
| egress | TAP + nftables + proxy | file-handle + userspace stack |

Moves between a Mac and an Ubuntu host always go through VOLUMES: the volume tree, image references and the container
spec; images are published multi-arch (amd64 + arm64). The R0 spikes confirm this table; see "R0 spike results".

### R-D10 Linux guests only; macOS stays as it is

**Decision.** herd runs Linux guests only and builds no macOS guest class. macOS-native delegation keeps Everdict's
current Seatbelt lane (Nomad raw_exec + Seatbelt + pf; PLT-89/90) unchanged: it is not moved into herd, and it is
excluded from the direct-mode retirement (PLT-110).

## Decisions this ADR makes

### A-1 Name

**Decision.** The product is `herd`; the components keep the spec's names (`herd-api`, `herdlet`, `herd-router`,
`herd-egress`, `herd-guest`). The repository is `everdict/herd`. Its visibility is not decided here: it is the
owner's call on PLT-111.

### A-2 Module and toolchain

**Decision.** The Go module is `github.com/everdict/herd` with `go 1.25`. Library code returns errors and does not
panic.

### A-3 License

**Decision.** herd is licensed under the Apache License 2.0 (the `LICENSE` already in the repository). It matches the
license of the Substrate API definition herd vendors, whose copyright and license notice are kept in the vendored file
and in `NOTICE`.

### A-4 The pinned Substrate API subset

**Decision.** herd pins Substrate's `api/ateapi/v1/ateapi.proto` at commit
`6d7b3f49f6154d52a1de46c94a1481868a5ed042` (sha256 in `api/ateapi/v1/UPSTREAM.md`) and serves these `Control` methods:
CreateActor, GetActor, ListActors, UpdateActor, DeleteActor, SuspendActor, ResumeActor; CreateTag, GetTag, DeleteTag;
CreateActorTemplate, GetActorTemplate, DeleteActorTemplate; GetActorEgressPolicy, CreateActorEgressPolicy,
UpdateActorEgressPolicy, DeleteActorEgressPolicy.
- The subset is cut mechanically by `internal/cmd/protosubset` from a byte-for-byte copy of the upstream file: the
  listed methods, every message and enum they reach, and the `resource`/`method` annotations. A test regenerates it
  and fails on any hand edit; another fails when a listed method is missing or an unlisted one appears.
- The protobuf package stays `substrate.ateapi.v1`, so full method names are wire-identical to Substrate's; only
  `go_package` changes. Consequence: one Go binary cannot link both Substrate's and herd's generated package (they
  register the same names). Everdict's integration is not Go, so this does not bite it.
- R0 generates message types only (protoc-gen-go v1.36.12, runtime google.golang.org/protobuf v1.36.12 — Substrate's
  own pin). The gRPC service stubs and the grpc dependency arrive with herd-api in R1.
- Not in the subset: RevertActor, ListTags, UpdateTag, ListActorTemplates, workers, atespaces, access policies,
  credential minting and the WorkerService. Adding one is a change to `subset.txt` and this ADR.

### A-5 The capability extension

**Decision.** herd's extension is the service `herd.ext.v1.Capabilities` (GetWorkerCapabilities,
ListWorkerCapabilities) returning `WorkerCapabilities`: worker, platform (Cloud Hypervisor or VZ), arch,
`suspend_max_fidelity` as Substrate's own `SnapshotFidelity`, `restore_family`, `portable_restore_family`,
`hypervisor_version`, and the `reason` a host declares less than its platform could.

### A-6 The hypervisor boundary

**Decision.** herdlet reaches a hypervisor only through `vmm.VMM`: Capabilities, Boot, Snapshot (VOLUMES or MEMORY),
Restore, Inspect, Delete.
- Presence is three-valued (gone, present, unknown). Delete answers gone only after verifying it; a VM that survives
  is present with `ErrDeleteNotVerified`; a call that times out or gets no answer is unknown with the reason.
- A snapshot that did not complete is not returned. A MEMORY snapshot restores only in its restore family
  (`ErrRestoreFamilyMismatch` otherwise); a VOLUMES snapshot restores anywhere.
- `vmm/vmmtest` is the contract. The in-memory fake (`vmm/fake`, with injected hangs, unreachable answers and a delete
  the hypervisor does not carry out) runs it in every `go test`; the Cloud Hypervisor and VZ backends must run it on
  real hosts.
- The backends sit behind build tags: `vmm/cloudhypervisor` (linux) and `vmm/vz` (darwin). In R0 they are stubs that
  answer a typed `*vmm.NotImplementedError` and presence unknown; R2 (PLT-114) implements them.
- (R2b, PLT-182) `vmm/vz`'s logic builds on every platform against its own hardware interface (`vz.Hypervisor`);
  only the Code-Hex/vz binding (`vz.Native`) sits behind `darwin && arm64 && cgo`, and `vmm/vz/vzfake` runs the
  contract and the backend's own tests in every `go test`. A Mac declares MEMORY only when validateSaveRestoreSupport
  and a real save/restore round trip both succeeded on it.
- `vmm.Fidelity` uses Substrate's `SnapshotFidelity` numbers (VOLUMES = 1, MEMORY = 3).

### A-7 One guest build for both architectures

**Decision.** The guest kernel is built from Cloud Hypervisor's kernel tree at `ch-release-v7.2.8-20261009` (commit
`639d0886248cd90799b0b590f7a62a1a3565a815`), the release the R0 spikes booted on both hypervisors. One shared
configuration fragment (`guest/kernel/herd-guest.config`) is merged onto `allnoconfig` together with a small
architecture fragment that may set only what cannot be shared (console, interrupt controller, PCI host, paravirt);
a test enforces that. `guest/build.sh` fails if kconfig drops a requested symbol. One initramfs list serves both;
herd-guest is `/init`. The output is `bzImage` for amd64 (Cloud Hypervisor) and `Image` for arm64 (Cloud Hypervisor
and Virtualization.framework).

### A-8 Restore family names

**Decision.** `microvm-ch-<arch>-<cpu-class>` with `arch` in {amd64, arm64} and a lower-case CPU feature class label;
`microvm-vz-arm64-<host>` with a lower-case host label; `microvm-volumes` for every VOLUMES snapshot. Hosts that
declare the same CPU class must be able to restore each other's memory snapshots; choosing the class (e.g. the CPUID
leaves Cloud Hypervisor checks) belongs to the Cloud Hypervisor backend in R2.

### A-9 Dependencies

**Decision.** R0 depends on google.golang.org/protobuf only. Hardware libraries (Cloud Hypervisor's API client,
Code-Hex/vz with cgo) enter only inside their backend packages, behind their build tags.

### A-10 herd-guest (R5, PLT-104)

**Decision.** `cmd/herd-guest` is `/init` of the guest and the agent inside it.
- **API.** It serves agent-substrate/env's `ateenv.v1alpha` ProcessService and FileSystemService, wire-compatible: the
  proto is vendored byte for byte from env at commit `281e86085bb0b6d3090ff3fa82d722cf0d9f2f0b`
  (`api/ateenv/v1alpha/UPSTREAM.md`), and a test compares herd's generated descriptor with the one env's own
  generated code embeds. env has no stat or list; herd adds them as `herd.ext.v1.FileInfoService` (StatFile,
  ListDirectory), so an env-only client is unaffected. The target container is chosen by the request metadata key
  `x-herd-container` (default: the first container of the template).
- **gRPC.** First served by `internal/grpcwire` (gRPC framing over the standard library's unencrypted HTTP/2) while
  grpc-go was not vendored; now grpc-go (A-12), with no wire change. `test/interop` (a separate module) checks the
  guest against grpc-go with env's own generated client.
- **Transport.** The guest listens on AF_VSOCK (the same in the guest under Cloud Hypervisor and
  Virtualization.framework) or a unix socket (tests, `serve -local`). The host side of Cloud Hypervisor's hybrid vsock
  (unix socket + `CONNECT <port>`) is `transport.DialHybridVsock`; VZ's native vsock dialer belongs to R2.
- **Detached exec.** Every process is Everdict's record `/everdict/exec/<id>/{cmd.sh,pgid,out,err,exit,in}` inside the
  target container (herd adds `meta.json`, the start request, and `in.closed`). herd-guest is bound read-only into each
  container at `/.herd/herd-guest`; `crun exec --detach` starts `herd-guest shim <dir>` there, which runs
  `/bin/sh cmd.sh` as a new session, appends stdout/stderr straight to `out`/`err`, writes `pgid` and then `exit`
  (code, or 128 + signal). `in` is a FIFO the shim reopens after each writer, so a guest restart is not end of input;
  stdin ends only when `in.closed` exists. The service keeps no process table: every call reads the record, so a
  restarted guest follows a running exec from the client's byte offsets and reports its exit. Signals go through
  `herd-guest signal <pgid> <sig>` exec'd in the container (pids are the container's). Timeouts are re-armed from
  `meta.json` after a restart.
- **Boot.** As PID 1: pseudo filesystems, then the virtio-fs share (tag `herd`) at `/mnt/volumes`, then the plan
  herdlet wrote at `.herd/actor.json` in the share, then every DurableDir volume as a directory `<share>/<name>`
  (a DNS label; an existing non-directory there, e.g. a symlink, is refused), and only then each container: image
  block device (erofs or ext4) read-only, an overlay on tmpfs on top, `config.json` from `guest/oci` with the volumes
  as bind mounts whose sources must lie inside the share, and `crun run --detach`. The container's process is
  `herd-guest cinit -- <argv>`, which reaps the shims reparented to it. `oci.Runtime` and `initd.Mounter` are the
  hardware boundaries; tests run them as fakes.

## Decisions for R1 (herd-api, PLT-113)

### A-11 Records and the all-in-one store

**Decision.** Actors, actor templates, tags, egress policies, workers and spaces are records in `store.Store`. The
store assigns uid and version; every update and delete names the uid+version it was read at, and a stale one is refused
(Aborted on the API); updates through the API must carry both. Implementations: `memstore` (in memory) and
`boltstore` (the all-in-one mode), both held to the `storetest` contract, which includes durability across a reopen. This replaces
the SQLite that R-D4 names for the all-in-one mode.
- **Why bbolt.** go.etcd.io/bbolt is pure Go (no cgo, so one static herd-api for amd64 and arm64), a single file,
  and its write transactions are serialized and fsynced on commit, so a precondition checked inside the transaction
  holds against every other writer of the file. A pure-Go SQLite (modernc.org/sqlite) vendors to about 144 MB for
  what herd-api needs from it — get, compare-and-swap, list by prefix — and cgo SQLite breaks the static build.
- **Not the multi-host store.** bbolt holds an exclusive file lock: one herd-api process per file. Several herd-api
  replicas (multi-host join and Nomad with more than one herd-api) need a shared store; that is Postgres, behind the
  same interface and contract, later.

### A-12 gRPC is grpc-go

**Decision.** herd-api (`substrate.ateapi.v1.Control`, `herd.ext.v1.Capabilities`, the herdlet link) and herd-guest
(`ateenv.v1alpha` ProcessService and FileSystemService, `herd.ext.v1.FileInfoService`) serve on grpc-go v1.83.2.
`internal/grpcwire`, the standard-library stand-in both used before grpc-go was vendored, is removed; this supersedes
A-10's "No grpc-go" bullet and changes no wire byte (same full method names, same protobuf messages). The service
descriptors are hand-written (`apiserver/service.go`, `guest/agent/service.go`) because protoc-gen-go-grpc is not
available where herd is built; each is checked against the proto's own service descriptor by a test, so a method
added to the proto without a handler fails. herd-api serves cleartext HTTP/2; until it terminates TLS itself, TLS is
terminated in front of it, since bearer tokens travel in the request metadata.

### A-13 The herdlet link

**Decision.** A herdlet dials herd-api and opens one bidirectional stream, `/herd.ext.v1.Herdlet/Link` (package
`link`); herd-api never dials a herdlet, and a test keeps dialers out of `apiserver`, `link` and `cmd/herd-api`. The
herdlet registers its worker name, class, labels, declared capabilities and capacity (slots, warm VMs per template);
herd-api sends work (boot, snapshot, restore, delete, inspect) and the herdlet answers each with a three-valued outcome:
done, failed (definitely not done) or unknown. No answer before the deadline, a broken link or a herdlet that is not
connected are unknown. A delete is done only with the VM verified gone. A herdlet credential registers only the worker
it names. Messages are JSON (gRPC content-subtype `json`) until the link gets a `.proto`.

### A-14 Workflows, durability and owed steps

**Decision.** SuspendActor (synchronous unless DURABILITY_MODE_ASYNCHRONOUS) snapshots at the template's preferred
fidelity capped by the worker's declared `suspend_max_fidelity`, verifies the object in the snapshot store against the
digest the herdlet answered, records key+digest in the actor record, and only then asks the herdlet to release the
VM. A step whose outcome is unknown stays owed on the actor (SUSPENDING, RESUMING or DELETING; the reason in the
`herd-owed` response trailer and the call's Unavailable status) and `Reconcile` retries it; DeleteActor removes the
record only after a verified gone and verified deletion of its snapshot objects. Fork is CreateTag{source_actor} (a
tag owns a copy of the snapshot) + CreateActor{actor_template, source_tag}.

### A-15 Scheduling, snapshot store and authentication

**Decision.** The scheduler places an actor only on a connected herdlet of its class with a free slot (slots stay
taken until a release is verified), matching labels, and for a MEMORY snapshot the same restore family; VOLUMES
restores anywhere; a warm VM of the template is preferred; otherwise it refuses with a typed reason per worker
(ResourceExhausted). The snapshot store is `snapstore.Store` with a local-disk implementation (fsync + rename, sha256
digest); S3 comes later behind the same interface. Authentication and per-space authorization are interfaces; this
round implements them with one static HS256 key (`auth.StaticKey`, roles read/write per atespace, a separate herdlet
credential).

## Decisions for R3 (herd-router and the herdlet tunnel, PLT-115)

### A-16 The tunnel: the herdlet dials the router

**Decision.** A herdlet dials herd-router as it dials herd-api and holds one control stream,
`/herd.ext.v1.Tunnel/Control` (package `tunnel`, JSON like the link). For each connection the router needs it sends
Open{id, vm, port}; the herdlet connects to the guest through its `herdlet.GuestDialer` (Cloud Hypervisor: hybrid
vsock, `cloudhypervisor.VMM.DialGuest`; VZ: native vsock, R2; tests: `vmm/fakeguest`) and opens a new outbound stream,
`/herd.ext.v1.Tunnel/Data` with `herd-tunnel-id`, carrying that connection's bytes in a small binary frame codec
(`application/grpc+herdframe`) — or answers Refused{reason}. No node has an inbound port; a test keeps dialers out of
`router`, `tunnel` and `cmd/herd-router` (whose one gRPC client is herd-api). Only a herdlet credential opens a
tunnel, only for the worker it names, and a data stream is paired only with an Open sent to that worker.
- `link.Work` names its `Cause` (suspend or delete). On a snapshot for suspend and on a release, the herdlet cuts the
  VM's streams with a typed reason (`actor-suspended`, `actor-deleted`) sent before the stream's end, and refuses new
  ones until the VM is booted or restored again; a snapshot that failed reopens it. Cutting at the snapshot keeps a
  client from reading output a MEMORY snapshot does not contain.

### A-17 herd-router

**Decision.** `cmd/herd-router` serves clients over HTTP/1.1 and prior-knowledge h2c and herdlets' tunnels over gRPC.
- **Naming and authn.** `ate-target-actor: <atespace>/<actor>`, Substrate's header and format. The bearer JWT is
  verified (the same `auth.Authenticator` as herd-api) and must grant write in that atespace — routing reaches exec and
  files — before anything is resumed or dialed; herdlet credentials are refused. herd-api calls carry the client's own
  token, so herd-api authorizes the resume too. The token is not forwarded to the guest.
- **Ports.** Ordinary requests go to the guest's API port (herd-guest, vsock 8080; `-default-port`) as h2c; Substrate's
  default is the actor's port 80. `CONNECT host:port` reaches another port as a byte tunnel resolved (and resumed)
  when the CONNECT arrives; unlike Substrate, the requests inside a CONNECT are not re-routed one by one.
- **Parking.** A request to an actor that is not RUNNING is parked: a SUSPENDED actor gets one ResumeActor shared by
  every parked request (on its own context, so a client that leaves does not abandon it), and the request is delivered
  once herd-api answers RUNNING and the worker's tunnel opens. Past the parking budget (`-parking-budget`, 30 s) the
  answer is a typed 503: HTTP 503 with `herd-reason: parking-budget-exceeded` and, for gRPC, grpc-status UNAVAILABLE in
  the same trailers-only response. If the actor's last known worker holds no tunnel to the router when the budget
  ends, the reason is `node-unreachable` instead, whether or not herd-api answered inside the budget (its error is
  added as detail). NotFound, DELETING and authorization failures are answered at once.
- **Long streams.** The budget bounds only the wait. A delivered request runs on the client's own context, the HTTP
  server has no read, write or idle timeout (only the header read is bounded), and gRPC streams have none. A cut stream
  ends with the reason in the `herd-reason` trailer (grpc-status UNAVAILABLE); the client re-attaches by exec id and
  offsets, and that request resumes the actor. An HTTP/1.1 CONNECT has nowhere to put a reason and is closed.
- **Behind NAT.** Herdlets keep their tunnel alive with gRPC keepalive pings; the router permits them every 10 s.

## Decisions for R4 (herd-egress, PLT-116)

### A-18 herd-egress: one policy model, decided by name, two plumbings

**Decision.** herd-egress (`egress`, `cmd/herd-egress`) enforces Substrate's own `EgressPolicy` — the message pinned
in `api/ateapi/v1` (A-4), not a herd copy: http, https (intercepted) and tls_passthrough rules, hostname patterns,
ports, `replace_headers` from a `credential_uri` or an `actor_jwt`. `egress/policy` compiles it with Substrate's
admission rules (pattern syntax, IP addresses refused as hostnames, no two rules tying on a name and port among the
rules that decide on the same input) and its precedence (exact name over wildcard, then a named port over all
ports); herd-api refuses an invalid policy with InvalidArgument on create and update.
- **Default-deny, host-side first.** No policy, an empty policy and a policy that does not compile all refuse
  everything. Before any rule is consulted, the `Guard` refuses host-side targets: IP literals, loopback, private
  (RFC 1918, ULA), link-local, CGNAT, multicast and reserved ranges, metadata endpoints and names
  (169.254.169.254, fd00:ec2::254, 100.100.100.200, `metadata.google.internal`, `*.internal`, `localhost`), and the
  host's and herd-api's configured addresses and names. Every address a listed name resolves to is checked again
  before the dial; a name with any host-side address is refused.
- **By name, never by address (Everdict defect PLT-180).** A decision is taken on the TLS ClientHello's SNI, on each
  HTTP request's authority, or on a CONNECT target (whose tunneled SNI or Host must name the same host). The gateway
  dials only the name it decided on, resolving it afresh for each connection; the address the VM connected to is
  never matched or dialed, only its port. A rotating listed host stays reachable; an unlisted host on a listed
  host's address stays refused.
- **Interception and credentials.** A ClientHello decided by an https rule is terminated with a leaf from the
  gateway CA (herdlet installs `CA.CertPEM` in the guest) and every request inside it is decided on its authority;
  TLS is re-originated to that name. The deciding rule's `replace_headers` replace a header the request carries with
  `prefix + credential`, resolved on the host (`Credentials`: `ate-secret://<class>/<name>/<tail>` through
  registered providers; `ActorJWTs`: ES256 JWTs naming the actor, reused while more than half their lifetime
  remains). The actor holds only a placeholder; a request without the header is forwarded without it.
- **Live updates.** Each actor's compiled policy is an atomic pointer read on every decision. The `Syncer` reads
  every bound actor's policy from herd-api's Control API every interval (default 1 s), so an update reaches the
  next request on an actor's open connections; an open passthrough connection keeps its decision until it ends, as
  in Substrate. An unanswered read keeps the last policy (unknown is not absent); NotFound is deny-all.
- **DNS.** The VM's resolver is herd-egress's `SyntheticDNS`: every A query is answered with one address that routes
  to the gateway, nothing else, and no query leaves the host.
- **Ubuntu plumbing.** `egress/nft` renders, per VM, a TAP and its own nftables table `inet herd_<id>`: anti-spoofing
  and non-IPv4 drop at prerouting (raw), every TCP connection from the VM redirected to herd-egress's transparent
  listener (`SO_ORIGINAL_DST` gives the port) and UDP 53 to its DNS, input from the TAP accepted only for those
  redirected flows, forward and output to the TAP dropped; drops are counted in named counters. The table is loaded
  before the link comes up. The renderer is golden-tested; `TestRealHostEgress` (HERD_EGRESS_REAL=1) applies it in
  network namespaces and measures the refusals. The VM gets a static address on a /30 (or wider) link.
- **macOS plumbing.** The VM's network device is a file-handle attachment into a userspace stack per VM
  (`egress.Stack`, `StackFactory`): TCP flows come out as `Flow`s into the same gateway, DNS to the gateway address is
  answered by `SyntheticDNS`, everything else is dropped. gvisor-tap-vsock behind that interface and the vz
  attachment land with R7 (PLT-118); `egress/stacktest` is the fake the gateway is tested through.
- Not yet: herdlet writing the bindings (actor ↔ TAP address) and installing the CA in the guest (R2), UDP and
  QUIC (refused, as in Substrate), STARTTLS, and the credential providers beyond a static map and a directory.

## R0 spike results

Measured by the supervisor on real hosts on 2026-10-30 (Everdict knowledge entry `0ce029cf`); recorded here because
they decide R-D9. R0's repository work did not boot VMs.

- **(a) Ubuntu, Cloud Hypervisor v54.0**, i7-1165G7, Ubuntu 26.04 / kernel 7.0.0-30, 1 vCPU / 512 MiB, guest kernel
  `ch-release-v7.2.8-20261009`: boot to init 0.28 s; snapshot 0.18 s (513 MiB: config.json, memory-ranges,
  state.json); restore→resume 0.35 s, guest state continued. With virtio-fs (virtiofsd 1.13.2,
  `--migration-mode=find-paths`, shared memory) + vsock: boot 0.28 s, snapshot 0.05 s, eager restore→resume 0.07 s,
  the guest kept writing to the volume. Restore on a second host (Core Ultra 5 226V, kernel 7.0.0-38) was refused:
  "Detected incompatible CPUID entry" (leaf 0x01 ECX, leaf 0x07 EBX/ECX/EDX). Memory restore therefore needs the same
  CPU feature class — R-D9's `microvm-ch-<arch>-<cpu-class>` is **confirmed**.
- **(b) macOS 26.2, M1**, Code-Hex/vz v3, ad-hoc signed: `validateSaveRestoreSupport` = true with virtio-fs + vsock;
  boot to init 0.175–0.205 s; the share mounted. `saveMachineStateTo` fails with VZErrorDomain Code=11 "permission
  denied" from an SSH session, from `launchctl asuser`, and from a launchd agent in `gui/<uid>`, also when saving
  under /tmp. Not yet tried: a Developer ID-signed binary in an unlocked console session. R-D9's macOS row is
  **confirmed**: Macs declare VOLUMES by default; MEMORY on a Mac stays unverified.
- **(c)** One kernel source booted on both: bzImage (x86_64) under Cloud Hypervisor, Image (arm64) under VZ.

## Consequences

- Everdict talks to herd and to real Substrate through one client; methods outside the subset are not available on
  herd.
- A suspend keeps memory only where the host declared it can, and the actor resumes at MEMORY only within the
  restore family; everywhere else it resumes at VOLUMES.
- Each hypervisor backend is testable without hardware through the fake and the contract; the real backends prove
  themselves by running the same contract on a KVM host and on a Mac.
